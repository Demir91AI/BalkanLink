# AGENTS.md

- Registration and sign-in classify service failures through the shared UI-only auth-error mapper and translate keys; unknown failures use a safe fallback — prevents raw service text without changing authentication policy.

- FormularPilot code lives in `src/lib/formularpilot/` and stays unwired from live pages until owner release approval — keeps production behaviour unchanged during 2.0.
- Every official-form fill pipeline is fail-closed: validate → preflight (hash + native fields) → edition gate → fill → read-back; never guess field names — prevents wrong or outdated forms reaching users.
- PDF field appearances use the locally bundled, hash-pinned Unicode font in `src/assets/fonts/` via `@pdf-lib/fontkit`; never load fonts remotely — BHS letters must print and no third-party font requests.
- Encrypted/XFA official forms are never decrypted or re-mapped; offer a clearly non-official answer sheet plus official links instead — respects publisher restrictions.
- `src/test/phase1/` pins routes, redirects, storage keys, hub imports, payment contract and family PDF mappings; update `baseline.json`/snapshots only with owner approval — prevents silent downgrades of legacy behaviour.
- The standalone letter-reply feature (card, sidebar entry, `?task=reply`, `reply` namespace) was removed on owner request; letter help stays only in the general Asistent chat — do not re-add it without owner approval.
- Release browser regressions in `tests/release/` use their own config against the existing localhost server without a webServer/build hook — permits source-only release checks without accidental publishing or invoking the legacy visual-build workflow.
- FormCenter/Viza are guide-first: legacy `/musterformular/*` URLs redirect via `LegacyMusterGuard` in `Layout` while route elements and Muster sources stay; official next steps come from `src/lib/guide-first/official-sources.ts`, where `verifiedOn` is set only after a primary-source check — keeps the cutover reversible and prevents unverified "official" claims.
- Kindergeld pilot derives ordered paper groups from all original locale records plus localized source-checked expansions; online groups stay separate and uncertainty is explicit; only the host supplies official application links — preserves content while preventing paper/portal order conflation.
- Kindergeld inline subfield/choice definitions are locale data keyed to stable paper group IDs and audited against `docs/kindergeld-final-field-inventory.json`; render them through FieldWalkthrough without answer widgets — preserves 30-group navigation while making every newborn-relevant option testable and understandable.
- Access decisions come from the server RPC `get_entitlement(uid)` (mirrored in `src/lib/entitlement.ts`, read via `useEntitlement`); legacy sources rank above new ones and are never capped — one source of truth prevents contradictory gates and downgrades.
- DokumentenCheck shares its pure validated upload/result contract with its server function; reserve/commit/release stays server-owned, old deployed text is displayed without inferred facts, and guide links default to the catalog — prevents mixed-release failures, fabricated deadlines and model-selected routes.
- Expensive Edge Functions meter through `_shared/usage.ts` → `reserve_usage`/`commit_usage`/`release_usage` (service-role only); rule values live in `_usage_rule`, trial grants only via the email-confirmed trigger and `entitlement_settings` switches (default off) — one atomic ledger with no user content prevents client-side quota bypass and premature rollout on the shared backend.
- FormCenter guides render inside `GuideFrame` and are gated by `decideGuideAccess` (`src/lib/guide-first/guide-access.ts`): with `monetization_v2_enabled` off or unreadable it equals the legacy isPremium||free-slug rule — prevents accidental lock-out or exposure before rollout.
- New €19.99/year membership is staged in `_shared/annual.ts` (exact-price allowlist, checkout gate) and applied only via service-role `apply_annual_subscription`, which never alters admin/lifetime/legacy-premium rows; checkout requires `annual_checkout_enabled`, a `STRIPE_ANNUAL_PRICE_ID` secret, and `annual_live_mode_allowed` for live keys — keeps billing inert until owner approval.
- All upgrade/paywall UI renders the single `MembershipOffer` (`src/components/membership/`) via `useMembership`; legacy lock components (PremiumModal, PremiumPaywall, FormularLock, SmartGuideLock, VisaGateCard, PremiumBenefitsSection, PlusCtaLabel) keep their APIs but delegate to it, and checkout is only invoked as `annual` when `annual_checkout_enabled` — one coherent offer without touching gate decisions or legacy Stripe records.
